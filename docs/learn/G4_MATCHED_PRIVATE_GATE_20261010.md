# G4 private confirmation: matched seed blocks

The G4-search cohort has five frozen children, each compared with its own G3 parent. The earlier evaluator averaged thirty maps per child and then applied an unpaired Mann–Whitney test to five candidate and five parent means. That discarded the matching and had very little power when one already mastered child retained its parent policy. No `G4-search` private seeds or family reservation existed when this design was changed.

Protocol v2 keeps two independent, committed 30-seed sets. In each set the evaluator saves the normalised return for every child, task and seed. It validates those private matrices against the child averages before any decision. For each seed, it averages across the five fixed children and the same nine tasks for candidate, matched G3 controls and every surviving ancestor. It chooses the strongest ancestor using the frozen lineage rule.

For candidate versus control and candidate versus strongest ancestor, the one-sided **exact paired sign test** counts positive and negative seed differences. Ties count as half an improvement for the probability measure and do not enter the binomial p-value. Each comparison requires `p < 0.01`, a positive mean paired gain and paired improvement probability at least 0.75. The existing mastered-task retention floors (0.90 mastery, at most 0.10 regression) are checked on the five child means. Both seed sets must pass. The protocol stores the evaluator hash and all scoring rules before the secret seeds are created; a later code change invalidates a frozen attempt.

The thirty seed blocks support a statement about these five frozen policies across new levels. They do not estimate how a sixth independently trained child would perform. The older G4-oracle results remain archived under their original unpaired protocol; they are not rescored to manufacture a promotion. If the v2 family fails, G3 remains official and another private try requires a new preregistered family and fresh hidden sets.
